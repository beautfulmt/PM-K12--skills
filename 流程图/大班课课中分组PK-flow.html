1. 课中分组PK主流程

本图只描述学生端体验链路；老师端仅作为触发方存在，不展开主讲端详细交互。

sequenceDiagram
    participant T as 老师(触发方)
    participant S as 服务端
    participant C as 学生端
    participant R as 排行榜/结算服务

    T->>S: 触发课堂分组PK
    S->>S: 校验当前课堂状态、在线人数
    S->>S: 以6人为目标组规模生成若干组

    alt 第1课/无历史数据
        S->>S: 随机分组
    else 第2课及以后
        S->>S: 读取上一课正确率
        S->>S: 按正确率分层匹配, 尽量使同层小组实力接近
    end

    S-->>C: 推送「PK开启」动画 + 组别信息
    C-->>C: 展示3秒开场仪式

    loop 覆盖课堂后续题目
        S-->>C: 下发当前题目PK状态(题号/本组分数/当前名次)
        C-->>C: 复用现有课堂答题页, 增加PK浮条
        C->>S: 提交个人答案
        S->>R: 汇总个人结果到本组总分
        R-->>S: 返回单题组排名、总榜变化、个人贡献
        S-->>C: 推送单题PK结果
        C-->>C: 全屏展示3秒单题结果与榜单变化
        C-->>C: 返回课堂, 等待下一题
    end

    alt 老师主动结束PK
        T->>S: 结束本轮PK
    else 课程题目结束
        S->>S: 自动结束本轮PK
    end

    S->>R: 生成总榜、组内6人称号、奖励结果
    R-->>S: 返回颁奖数据
    S-->>C: 推送总榜 + 个人称号卡 + 小组称号卡
    C-->>C: 展示颁奖仪式

    opt 学生中途断线
        C--xS: 心跳中断
        S->>S: 保留当前题状态15秒
        C->>S: 重新连接
        S-->>C: 恢复当前题/单题结果/终榜状态
    end

2. 分组匹配逻辑

首课完全随机；第2课开始基于上一课正确率做同层匹配，让后续PK更公平。

flowchart TD
    A[老师触发本轮PK] --> B{是否存在上一课正确率数据}
    B -- 否 --> C[随机打散在线学生]
    C --> D[按在线人数/6生成若干组]
    B -- 是 --> E[读取每位学生上一课正确率]
    E --> F[按正确率从高到低排序]
    F --> G[分层匹配, 让相近正确率学生优先进入同层PK池]
    G --> H[按6人目标组规模生成小组]
    D --> I[输出本轮组信息]
    H --> I
    I --> J{是否存在尾组不足6人}
    J -- 否 --> K[正式开场]
    J -- 是 --> L[尾组按边界规则处理]
    L --> K

3. 单题结算与最终颁奖

每题都有3秒强打断结果页；整轮结束后再展示总榜和组内6人称号卡。

flowchart TD
    A[学生提交答案] --> B{是否答对}
    B -- 是 --> C[个人得分入账]
    B -- 否 --> D[本题个人得分为0]
    C --> E[累加到本组总分]
    D --> E
    E --> F[刷新单题小组榜和全程总榜]
    F --> G[展示3秒单题结果页]
    G --> H{是否为最后一题/老师已结束}
    H -- 否 --> I[回到课堂继续下一题]
    H -- 是 --> J[生成总榜Top3]
    J --> K[生成组内6人鼓励称号]
    K --> L[展示最终颁奖仪式]
