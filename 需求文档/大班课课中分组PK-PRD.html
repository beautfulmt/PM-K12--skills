一、需求背景

1.1 现状问题

  • 课中答题有参与，但缺氛围：学生虽然会跟随课堂答题，但单题答完后缺少“我和别人一起在参与”的群体反馈。
  • 整节课缺少持续性的激励线：如果只做单题答题，课堂中段容易掉状态，学生对自己每一道题的贡献感不强。
  • 只有终局榜会显得链路断裂：如果 PK 只在开始和结束时出现，中间缺少阶段性结果，学生很难持续感知比赛推进。

1.2 业务目标

在大班课课中引入“分组 PK”机制，让后续课堂题目都自动纳入小组积分体系，并通过每题结束后的 3 秒结果动效和整轮结束后的颁奖仪式，形成一条覆盖整节课的鼓励式互动主线。

  • 提升课堂答题的持续参与度
  • 强化学生对“小组荣誉感”和“个人贡献感”的感知
  • 让整节课中的每道题都能被组织到统一激励链路中

1.3 用户价值

  • 学生：每答一道题都会产生可见反馈，不只是“做完题”，而是“为小组加分”。
  • 老师：通过触发 PK 把后续课堂题目自动组织成更强的互动节奏。
  • 家长：更容易感知孩子在一整节课中的参与感和课堂获得感。

二、需求目标

目标类型 描述 衡量指标 目标值
核心目标 提升整轮PK题目的学生参与连续性 PK覆盖题目的人均提交次数 较基线 +10%
核心目标 提升课中互动的仪式感和可感知度 单题结果页有效曝光率 ≥ 90%

4.2 核心业务规则

规则项 规则描述
组规模 按在线人数 / 6 自动生成若干组，理想组规模为 6 人；尾组按边界规则处理。
首课分组 无历史数据时，完全随机分组。
后续课分组 读取上一课正确率，按正确率做同层匹配，让后续 PK 更公平。
积分口径 每个学生答对题目后，个人得分累加到本组总分；整轮以小组总分做排名。
结果节奏 每题结束后全屏展示 3 秒单题结果；老师结束整轮后，再展示总榜与颁奖。

五、详细方案

一级模块 二级功能 原型 描述
PK开场 分组揭晓

0、功能说明

  • 老师触发课堂 PK 后，学生端进入横屏开场页，明确本轮 PK 已正式开始。

1、展示内容

  • 显示当前所在组别、组名、组人数、PK覆盖题量、结果节奏说明。
  • 显示本轮目标：冲榜、全员参与、小组加分逻辑。

2、展示时长

  • 默认全屏展示 3 秒后自动进入课堂题目。
分组规则说明

0、首课规则

  • 第一节课无历史数据，完全随机分组。

1、后续课规则

  • 从第二节课起，读取上一节课正确率数据做同层匹配，尽量让相近水平的小组进行PK。
  • 目标是让对战公平，而不是单纯随机分配。

2、边界说明

  • 若存在尾组不足 6 人，由服务端按预设边界策略处理，不要求学生端做额外干预。
课中跟随 课堂答题浮条

0、功能说明

  • 不重做课堂答题主页面，而是在现有课堂题目页上叠加 PK 状态条和组分看板。

1、顶部信息

  • 显示当前 PK 状态、题目进度、本组累计总分、班级当前名次。

2、右侧看板

  • 显示本组累计总分、组内贡献Top、当前追分差距。

3、核心逻辑

  • 学生仍按原有答题链路作答，提交后再进入单题结果页。
全程覆盖

0、覆盖范围

  • 本轮 PK 从老师触发后开始，覆盖后续整节课中的课堂题目，直到老师主动结束或题目自然结束。

1、节奏要求

  • 学生在“答题页 → 单题结果页 → 回到课堂下一题”的节奏中循环。
单题结果 强打断结果页

0、功能说明

  • 每一道题结束后，学生端全屏展示 3 秒单题结果页，增强仪式感。

1、展示内容

  • 显示个人本题是否答对、个人得分变化、本组本题得分、本组当前总分和名次变化。
  • 展示本题 Top3 小组，补齐中间反馈的缺失。

2、展示时长

  • 强打断展示 3 秒，到时自动回到课堂下一题，不需要学生手动关闭。
单题积分入组

0、积分口径

  • 每个学生的答题得分都会累计到本组总分。

1、设计意图

  • 强调“每个人都参与、每个人都贡献”，不是小组选代表答题。
阶段榜单 中程轻榜态

0、功能说明

  • 除单题结果页外，在关键节点还可展示轻量化中程榜单页，帮助学生感知整轮进度。

1、展示内容

  • 班级Top榜、本组累计分、本组当前名次和追分差距。

2、展示时长

  • 该页同样为短停留态，可自动消失，不打乱课堂下一题节奏。
总榜颁奖 班级小组总榜

0、功能说明

  • 老师结束本轮 PK 后，学生端展示全班小组总榜，至少给出第1、2、3名。

1、展示内容

  • 展示班级 Top3 小组、本组最终名次、本组总分、我的个人贡献分。

2、结果定位

  • 这是一轮完整 PK 的终局页，区别于每题的阶段结果页。
结束触发

0、结束条件

  • 老师主动结束本轮 PK，或整轮覆盖题目全部结束。

1、学生端表现

  • 结束后不再展示“下一题PK”链路，而是进入总榜和颁奖链路。
组内称号 6人鼓励称号

0、功能说明

  • 因为每组固定为 6 人，终局时为组内 6 位学生各发一个称号，强化鼓励式教育。

1、称号示例

  • MVP、最快答题王、稳定输出王、最佳进步奖、团队助攻王、坚持闪耀星。

2、设计原则

  • 尽量做到每个学生都有自己的高光，不让称号只集中在少数高分学生身上。
异常处理 断线重连

0、功能说明

  • 学生在课中断线后，需要恢复到正确的 PK 状态，而不是简单返回课堂首页。

1、恢复策略

  • 服务端保留当前题状态 15 秒。
  • 若已提交，恢复后进入本题结果页；若未提交，则恢复剩余倒计时。

2、超时处理

  • 超出恢复窗口后，本题按未作答处理，但学生仍可继续参与后续题目和终局颁奖。
关键设计原则：这不是单道题的临时活动，而是一条贯穿整节课后续题目的互动主线。学生端核心体验必须做到“题题有反馈、过程有阶段榜、结束有仪式感、每个人都有称号”。

六、异常与边界处理

序号 异常场景 处理方案 兜底策略
1 在线人数不足，无法按6人完整成组 服务端按边界规则处理尾组，学生端只展示最终组结果 不把复杂分组逻辑暴露给学生
2 学生中途断线 保留15秒状态，恢复后回到正确的题目/结果/终榜状态 超时按未作答处理
3 单题结果接口延迟 展示“结果计算中”loading，短暂阻塞返回课堂 超过阈值则直接回课堂，并在下一题前补发榜单
4 老师中途结束PK 学生端立即终止后续单题结果链路，直接进入总榜页 已完成的题目结果继续计入总榜
5 奖励/称号计算失败 先展示总榜，称号页延迟补发 显示“称号生成中”，后台重试

七、数据埋点

序号 埋点名 触发时机/交互 埋点位置 埋点类型 参数名 参数类型 参数值 备注
1 pk_start_show 学生端展示PK开场页 学生端 曝光 groupId, groupMemberCount, lessonPhase string, int, string 组ID/组人数/课次阶段 用于统计开场触达率
2 pk_follow_show 答题页显示PK浮条 学生端 曝光 questionId, roundNo, groupRank string, int, int 题目ID/题序/当前名次 用于统计课堂跟随覆盖率
3 pk_answer_submit 学生提交答案 学生端 点击 questionId, isCorrect, submitMs, personalScore string, bool, int, int 题目ID/是否正确/耗时/个人得分 用于贡献与速度分析
4 pk_question_result_show 单题结果页展示 学生端 曝光 questionId, groupScore, groupRank string, int, int 题目ID/组分/组名次 用于统计阶段反馈触达率
5 pk_mid_rank_show 阶段榜单页展示 学生端 曝光 roundNo, myGroupRank, myGroupScore int, int, int 题序/名次/组分 用于判断中程反馈是否有效
6 pk_final_rank_show 总榜页展示 学生端 曝光 finalRank, finalScore, contributionScore int, int, int 最终名次/组总分/个人贡献 用于终局分析
7 pk_title_award_show 组内称号页展示 学生端 曝光 myTitle, groupId string, string 我的称号/组ID 用于评估鼓励机制
8 pk_reconnect_result 断线重连结束 学生端 曝光 recoverStatus, currentStep string, string 恢复成功/失败、恢复到的链路节点 用于排查课中稳定性

通用参数：courseId、lessonId、classroomId、studentId、grade_q 会作为默认公共参数透传。

八、上线计划与灰度策略

8.1 上线节奏

阶段 时间 范围 关注指标
灰度1期 待定 指定班级白名单 开场触达率、单题结果曝光率、崩溃率
灰度2期 待定 20% 课次 提交次数、单题结果完整率、重连成功率
全量发布 待定 100% 目标班级 参与率、中程反馈有效性、称号页完成率

8.2 回滚方案

  • 若课堂稳定性异常，可关闭 PK 开场与结果页，仅保留原有答题流程。
  • 若终局称号链路异常，可只关闭称号页，保留总榜页。
  • 若同层匹配数据异常，可回退到全量随机分组策略。
