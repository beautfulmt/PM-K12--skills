v1.9
【问题】：PRD 章节原本是 11 章全固定必出，小需求（如纯文案调整）也被迫硬塞流程图、灰度策略等用不上的章节，文档冗余

【思路】：
1. 章节从「固定必出」改为「按需求大小裁剪」：核心骨架（项目信息+版本记录、需求背景、需求目标、详细方案）始终保留；其余 6 章（需求概述/流程图/异常边界/数据埋点/上线计划/附录）按需求复杂度可整章省略
2. 保留章节的相对顺序不变，编号跟随实际保留章节连续重排，不跳号
3. 不得默默省略：在需求确认阶段（1.3.1）先列出本次保留/省略哪些章节及原因，经用户确认后再写
4. 产出物联动：若省略「流程图」章节，则整步跳过、不产出流程图 HTML 文件
5. 迭代时若新需求触及了之前省掉的章节，需先告知用户再补回该章节并按序插回
6. 更新到 edu-pm-prd（2.2/1.3.1/步骤四/5.2/5.3）+ SKILL.md


v1.8
【问题】：产物原本按「类型」平铺在根目录（需求文档/原型/流程图/…），所有需求混在同一批文件夹里，需求一多就分不清哪些文件属于哪个需求

【思路】：
1. 改为按「需求名」嵌套：项目根目录下先以需求名建一个顶层文件夹，该需求的 需求文档/原型/流程图/原型截图 都作为它的子目录，不同需求互不混放
2. scripts/、启动原型导出服务.command、.handoff/ 仍为所有需求共享，留在项目根目录
3. 受影响的相对路径：原型 HTML 引用导出脚本由 ../scripts/ 改为 ../../scripts/（多嵌套一层）；PRD↔原型↔流程图 仍同级，iframe src 不变
4. 导出服务 prototype_server.py 改为扫描 [需求名]/原型/*.html（兼容旧扁平 原型/*.html），截图按原型所在位置输出到 [需求名]/原型截图/（旧结构回退根 原型截图/）
5. init.sh 不再预建产物类型目录，只建共享的 scripts/ 和 .handoff/，需求子目录写需求时按需创建
6. 旧的扁平产物保持原位不动，新旧结构并存
7. 数据分析/需求挖掘/验收清单 一并纳入同一需求目录：一个 [需求名]/ 下最多含 7 类子目录（需求文档/原型/流程图/原型截图/需求挖掘/验收清单/数据分析）+ 沟通记录.md
8. 建立统一「需求目录归属规则」：谁先开工谁建家——任何工作流落盘前先查根目录是否已有同名 [需求名]/，有则复用、无则新建；不假设 PRD 先行，先做需求挖掘/数据分析也能独立以需求名建家，后续步骤复用同一目录；子目录用到才建，不预建空文件夹
9. 更新到 edu-pm-prd / demand / acceptance / data-analysis / SKILL.md / init.sh / prototype_server.py

v1.7
【问题】：原型导出服务之前用 5 秒轮询 LaunchAgent 守护，只要端口空就自动拉起完整服务（含 Playwright/Chromium），导致用户关闭终端后它又被拉起，占用资源且用户不感知

【思路】：
1. 把"常驻"拆成两层：极轻 launcher（~5MB，只监听 8766 端口）+ 完整导出服务（8765，按需拉起）
2. launcher 唯一职责：收到 POST /api/launch 时用 `open` 唤起「启动原型导出服务.command」
3. LaunchAgent 只拉 launcher，不再轮询 8765 端口
4. 浏览器 JS 新增降级：先 ping 8765，失败就 POST 8766 让 launcher 去拉完整服务，再等 30s 服务起来继续导出
5. 解决 LaunchAgent 沙箱读不到 ~/Documents 的问题：把 launcher.py 装到 ~/Library/Application Support/pm-prototype/，项目目录通过环境变量 PROTOTYPE_PROJECT_DIR 传入
6. 更新到 edu-pm-workflow assets（scripts/prototype_launcher.py、setup_prototype_export_watcher.sh、prototype-export-client.js）
